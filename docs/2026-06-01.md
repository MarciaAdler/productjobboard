# Updates — 2026-06-01

## Goals

- Expand job sources beyond the 8 ATS platforms already integrated
- Filter board to US + global remote only
- Always show salary on every job card ("Salary not listed" when absent)
- Improve description legibility — strip HTML artifacts, code fragments, garbled entities
- Result: 486 US/remote PM jobs, up from 335

---

## New sources added

### Remotive (`server/src/scrapers/remotive.ts`)
- **Endpoint:** `GET https://remotive.com/api/remote-jobs?category=product-management&limit=100`
- No auth required
- Salary field is a freeform string (e.g. "$80k – $100k") — passed through `parseSalary`
- `candidate_required_location` field used to filter US + worldwide jobs (exclude Europe-only, Asia-only listings)
- Returns 5 PM jobs currently (category is niche — Remotive's product-management category is small)

### RemoteOK (`server/src/scrapers/remoteok.ts`)
- **Endpoint:** `GET https://remoteok.com/api?tag=product-manager`
- Requires `User-Agent: Mozilla/5.0` header to avoid 403
- First array element is a legal notice — skipped with `.slice(1)`
- `salary_min` / `salary_max` are integers (USD) — cleanest structured salary data of any source
- All jobs are remote by definition — always passes the US/remote filter
- Returns ~53 PM jobs

### The Muse (`server/src/scrapers/themuse.ts`)
- **Endpoint:** `GET https://www.themuse.com/api/public/jobs?category=Product+Management&location=United+States&page={n}&descending=true`
- No auth required
- Category must be `Product+Management` (not `Product`) — the latter returns only 8 jobs vs 2,286+
- Fetches pages 0–4 in parallel (100 listings max per run)
- Filters to jobs published within the last 90 days — The Muse sometimes surfaces stale aggregated listings
- No structured salary available via the API
- Returns ~52 PM jobs after freshness filter

## US + Remote filter (`server/src/utils/filterUS.ts`)

Added a post-processing filter in `scrapers/index.ts` that runs after all scrapers complete. Rules:

1. **Always include:** `remotive` and `remoteok` source jobs (remote-only platforms)
2. **Include if:** `isRemote === true`
3. **Include if:** location contains US indicators (state abbreviation after comma, "United States", "USA", "Remote", "North America", etc.)
4. **Exclude if:** location contains specific non-US city/country terms (London, Berlin, Amsterdam, Sydney, Bangalore, etc.)
5. **Default:** include (better to over-include than miss US jobs with ambiguous location strings)

85 non-US jobs were filtered on the first run — mostly Recruitee (bunq = Netherlands) and Personio (European companies) and some Ashby/Greenhouse roles posted for offices outside the US.

**Decision:** Conservative filter — include by default when ambiguous. The alternative (require positive US confirmation) would drop too many valid remote roles that don't explicitly say "United States" in their location string.

## Salary always visible

Both `JobCard.tsx` and `JobDrawer.tsx` now always render the salary field:
- When salary data exists: shown in `text-emerald-700` (green)
- When absent: shows "Salary not listed" in `text-gray-400`

This makes it immediately clear to users whether compensation is disclosed, rather than the field simply not appearing.

**Salary data sources by quality:**
- RemoteOK: best — `salary_min`/`salary_max` as integers
- Lever: `salaryRange` string (e.g. "$140k – $220k")
- Ashby: structured via `includeCompensation=true` — `compensationTierSummary` string + tier components
- Remotive: freeform salary string
- All others: no salary data in API response

## Ashby compensation extraction

Updated `server/src/scrapers/ashby.ts` to call `?includeCompensation=true`. When the `compensation` object is present:
- Uses `compensationTierSummary` (e.g. "$257K – $335K • Offers Equity") as `salaryRaw`
- Strips the equity portion (splits on "•") before passing to `parseSalary`
- Falls back to reading `compensationTiers[].components[]` for `minValue`/`maxValue` integers

This turned Ashby from 0 salary disclosures to ~15+ jobs showing compensation.

## Description cleanup (`server/src/utils/htmlToText.ts`)

Rewrote the HTML-to-text pipeline to produce clean, readable prose:

1. **Block element newlines** — insert `\n` before `</p>`, `</div>`, `</li>`, `<br>` etc. before stripping tags, preserving paragraph structure
2. **Entity decoding** — handles `&amp;`, `&lt;`, `&gt;`, `&nbsp;`, `&mdash;`, `&rsquo;`, `&#39;`, and numeric entities (`&#8203;` etc.)
3. **Code artifact removal** — filters out lines matching CSS selector patterns (`.class {`), CSS property lines (`color: red;`), and lines with excessive special characters likely to be code fragments
4. **Whitespace normalization** — collapses multiple spaces, normalizes 3+ newlines to 2

**Decision:** Line-level filtering (remove whole lines that look like code) rather than regex substitution on the full text. This is more reliable for removing CSS/JS fragments that slip through HTML parsers when job descriptions include inline `<style>` blocks or template artifacts.

## Known limitations

- **The Muse freshness:** The 90-day cutoff mitigates stale listings but The Muse's `publication_date` reflects when the listing was first added to their platform, not when it was posted at the company. Some listings may be stale at source.
- **RemoteOK salary coverage:** Only 7 of ~58 PM jobs had non-zero salary values. Most companies don't fill in the salary fields even when the platform supports it.
- **Personio has no post date:** All Personio jobs default to "Just now" since the JSON feed doesn't include publication timestamps.
- **US filter is conservative:** Some non-US remote jobs (e.g., "Remote – Europe") may pass through if they don't explicitly mention a country. These would appear on the board but are correctly labeled as remote.
