# Updates — 2026-05-22

## Changes in this session

### 1. Location filter

Added a `LocationFilter` dropdown component (`client/src/components/LocationFilter.tsx`) that lets users narrow jobs by city or remote status.

**How it works:**
- Options are derived dynamically from the loaded job set — no hardcoded city list
- Extracts the first segment of each `job.location` string as the city (e.g. "San Francisco, California, United States" → "San Francisco")
- "Remote" option maps to `job.isRemote === true`, so it catches remote jobs regardless of how the location string is formatted
- Top 12 cities by job count are shown, each labeled with their count (e.g. "San Francisco (18)")
- Composes with search and date filters via the same `useMemo` pipeline in `App.tsx`

**Decision:** Dynamic dropdown over static pills. Location data varies too much across ATS sources to hardcode a useful set of options — deriving from the data guarantees the options are always valid and reflect what's actually available.

### 2. Sub-24h posting time precision

Updated `StatusBadge` to show minutes/hours for recently posted jobs rather than "Today".

**Changes:**
- `client/src/utils/dateHelpers.ts`: replaced `formatDaysAgo(days: number)` and `daysAgoColor(days)` with `formatTimeAgo(postedAt: string)` and `timeAgoColor(postedAt: string)` — both compute from the ISO timestamp directly rather than the pre-computed `daysSincePosted` integer
- `client/src/components/StatusBadge.tsx`: prop changed from `days: number` to `postedAt: string`
- `JobCard` and `JobDrawer` updated to pass `job.postedAt`

**Display logic:**
- < 1 min → "Just now"
- < 60 min → "Xm ago"
- < 24 h → "Xh ago" (green badge)
- < 7 days → "Xd ago" (blue badge)
- < 30 days → "Xd ago" (gray badge)
- 30+ days → "Xmo ago" (light gray badge)

**Decision:** Computing from the raw timestamp client-side gives full precision without adding any new fields to the Job interface or the server response.

### 3. Hourly client-side auto-refresh

`useJobs` now sets a `setInterval` to re-fetch `/api/jobs` every 60 minutes. The server cache TTL is 30 minutes, so each client-triggered refresh is guaranteed to return data that is at most 30 minutes old.

The UI footer was also updated: the source list was removed in favor of a clean `"X roles found · updated every hour"` line that stays accurate regardless of which ATS sources are active.

### 4. New ATS sources: Workday, Recruitee, Personio

Expanded from 5 live ATS sources to 8. Total jobs went from ~146 to ~335.

#### Workday (`server/src/scrapers/workday.ts`)
- **Endpoint:** `POST https://{tenant}.{wdServer}.myworkdayjobs.com/wday/cxs/{tenant}/{board}/jobs`
- **Body:** `{"appliedFacets":{},"limit":20,"offset":0,"searchText":"product manager"}`
- **No auth required** — this is the same endpoint Workday's own job board frontend calls
- Paginates up to 100 results per company
- `postedOn` field is a human-readable string ("Posted 3 Days Ago") — parsed to an approximate ISO date via regex
- Companies: Salesforce, Adobe, Capital One, Zendesk, Workday itself
- Yields ~61–77 PM jobs depending on timing
- **Decision to use searchText:** Narrows Workday results to PM-relevant titles at the API level, reducing unnecessary requests for non-PM jobs. The PM title regex filter still runs on results as a secondary pass.

#### Recruitee (`server/src/scrapers/recruitee.ts`)
- **Endpoint:** `GET https://{slug}.recruitee.com/api/offers/`
- No auth, returns all published offers
- `published_at` format is `"YYYY-MM-DD HH:MM:SS UTC"` (not ISO 8601) — normalized on ingest
- Salary structured data available when companies fill it in
- Mostly European companies; US PM coverage is limited
- Companies: bunq, betty-blocks, cm, trusted-shops

#### Personio (`server/src/scrapers/personio.ts`)
- **Endpoint:** `GET https://{slug}.jobs.personio.{de|com}/search.json`
- Returns a JSON array; no auth required
- Description field is empty in search.json — full descriptions require parsing the XML feed (not implemented yet)
- `postedAt` is not available in the JSON response; all Personio jobs default to the current timestamp (acknowledged limitation)
- Mostly European companies
- Companies: Vivid Money, Spryker, Personio

## Known limitations added in this session

- **Workday `postedOn` is approximate:** "Posted 3 Days Ago" → subtract 3 days from now. The actual post date could be off by up to 24 hours. No sub-day precision is possible from the Workday search endpoint without fetching individual job detail pages.
- **Personio has no post date:** All Personio jobs show "Just now" in the time badge because the search.json endpoint doesn't return a creation/publication date.
- **Recruitee and Personio are European-weighted:** These ATS platforms have limited penetration among US-based PM-heavy tech companies. Coverage from these sources will remain small until more US companies using them are identified.
